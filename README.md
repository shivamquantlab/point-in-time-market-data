# Point-in-Time Market Data

## Research question
What value could a researcher actually have known on a historical decision date when source records arrive late or are restated?

## Methodology and formulas
For a requested field and decision date t, the snapshot keeps records satisfying both effective_at <= t and available_at <= t. For each symbol it selects the latest (effective_at, available_at) pair. This bitemporal rule prevents a later publication or restatement from leaking into an earlier decision.

## Assumptions and limitations
- Dates have daily granularity; intraday release times and exchange calendars are not modeled.
- The demo uses hand-authored synthetic values with an explicit later revision. They are not prices or real company fundamentals.
- A production store also needs source identifiers, timezone policy, corporate-action handling, missing-data rules, and immutable vendor snapshots.
- This utility does not establish that a chosen dataset is point-in-time complete or free of survivorship bias.

## Reproducibility
With Python 3.11 or newer, run python -m pip install -e ".[test]", then python -m pytest and pit-demo. The experiment has no network access or credentials and writes reports/pit_snapshot.png plus reports/summary.json. The included report is regenerated by the same command.
